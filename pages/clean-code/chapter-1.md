*   **Code is permanent:** Code captures exact requirements. Higher-level languages will not replace it.
*   **Bad code destroys productivity:** Rushing creates a "mess" that slows teams to zero and triggers failed, massive "grand redesigns."
*   **Professionalism:** Blaming managers or tight schedules for bad code is unprofessional. The *only* way to go fast is to keep code clean.
*   **What is Clean Code:** It reads like well-written prose, does one thing well, includes tests, avoids duplication, and shows the author cares.
*   **Core Traits of Clean Code:** No duplication, does exactly *one thing*, highly expressive, and uses tiny abstractions (e.g., wrapping collection searches to allow future changes).
*   **The Expectation:** Clean code reads exactly as you expect. Beautiful code makes the programming language look like it was built specifically for the problem.
*   **We Are Authors:** Programmers read code >10x more than they write it. Making code easy to read actually makes it easier to write.
*   **The Boy Scout Rule:** Always leave the code a little cleaner than you found it (e.g., rename one variable, split one function, remove one duplication).
